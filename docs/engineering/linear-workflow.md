# Linear Development Workflow

Linear becomes the work contract once an issue exists. The issue should contain the goal, acceptance
criteria, explicit decisions, dependencies, and owners. Repository docs capture only durable rules;
they do not duplicate every issue discussion.

For parallel or multi-device work:

1. Read the issue and existing claims.
2. Post the work claim from `.agents/coordination.md`.
3. Use one Linear-scoped branch/worktree and name a single writer for shared files.
4. Push a clean branch and post a handoff before switching devices.
5. Keep status active until acceptance evidence is complete; report unverified OS/device paths.

The hackathon workflow relies on implementer-owned tests, automated checks, and final diff
self-review. Additional specialists may be used when valuable but are not default blockers.
